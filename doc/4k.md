# MuMu 4K 分辨率

模拟器可以使用横屏 `3840x2160`，原有 `1280x720` 继续可用。
Alas 不修改模拟器的渲染分辨率；截图会缩为 `1280x720` 后再进行识别、OCR 和错误截图缓存。

推荐使用 `nemu_ipc` 截图和 `MaaTouch` 控制。SDK 的原始采集缓冲区会重复使用，
4K 图像先缩小，再进行色彩转换和翻转。ADB、uiautomator2、Hermit 和 nemu_ipc
控制会映射到原生像素；MaaTouch、minitouch 保留原有触控范围换算。

截图频率沿用现有设置接口：

| 场景 | 截图间隔 |
| --- | --- |
| 普通任务 | 原有配置；nemu_ipc 为 0.1–0.2 秒 |
| 点击、长按、滑动、拖动后 | 临时 0.1 秒；页面确认后恢复，未收到确认时最多持续 2 秒 |
| 普通战斗加载 | 明确识别加载画面后为 0.5 秒；进入战斗后恢复战斗配置 |
| 登录等待 | 沿用 1 秒等待；交互后临时恢复高频，登录结束或异常后恢复普通配置 |
| 自动战斗 | 原有战斗配置；不通过静态画面推断空闲 |

演习血量检测和手动战斗不增加等待降频。任务开始、页面切换确认后恢复普通频率。
这些策略控制 Alas 的采集频率，不改变游戏的帧率设置。

开发时可用 `device.screenshot_interval_set('wait')` 声明非关键等待，完成后调用
`device.screenshot_interval_set()` 恢复普通配置；有异常出口时应使用 `finally`。
`'active'` 临时提高采集频率，`'confirmed'` 结束临时高频并恢复进入前的间隔。
低频等待的确认计时应基于经过时间，避免额外的检查次数要求延长超时。

这是游戏画面为 16:9 的 4K 适配，不包含 4096x2160、超宽屏、黑边裁剪或特殊 UI 布局。
其他尺寸仍会要求人工处理。主界面装扮、战斗 UI 等要求仍遵循项目原有支持范围。
