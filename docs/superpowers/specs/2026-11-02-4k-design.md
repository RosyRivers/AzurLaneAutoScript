# 4K screenshots and scene intervals

User-approved requirements: retain MuMu `nemu_ipc`, reuse its capture buffer,
downsample before RGB conversion/vertical flip, and retain only 1280x720 frames
for recognition and error history. Support 3840x2160 alongside existing 1280x720.
Keep the simulator's rendering resolution unchanged.

Use the existing device classes and interval API. Store native screen dimensions
separately from the recognition image. Convert logical coordinates once at native
input boundaries; preserve existing minitouch/MaaTouch and scrcpy conversions.
Include direct dorm feeding inputs and fallback screenshot methods.

Ordinary tasks retain their configured interval, auto combat retains its existing
combat interval, and explicit noncritical loading waits use 0.5-1 seconds. Input
temporarily restores 0.1-0.2 second screenshots until confirmation; task/page
transitions restore ordinary settings. Do not infer waiting from static images.
Do not change exercise HP monitoring or manual combat cadence. Timers requiring
both elapsed time and polling counts must not gain a longer effective timeout.

Chosen approach: normalize at the device boundary, preserving existing assets,
OCR regions and task coordinates. Rebuilding native 4K assets is unnecessarily
broad; scrcpy adds encoding and recognition tradeoffs and is not the chosen default.

Keep Python 3.7 compatibility, repository style and existing dependencies. Test
buffer lifetime/resolution changes, orientation, native input scaling, scene
restoration and 720p regressions. Verify real 4K capture/recognition without
automatically running resource-consuming tasks or changing the installed copy.
